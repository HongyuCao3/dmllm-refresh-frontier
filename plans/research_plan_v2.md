# 研究计划 v2：在同等质量下降低多模态扩散模型的缓存刷新占比

2026-10-27 · Hongyu Cao

> 在线可编辑版本：<https://claude.ai/artifact/Aw3jJnaReYrrrsWJ2R8tEC>

## 版本说明

v2 的核心目标是：**在保持输出质量不变的前提下，降低全量重算步数的占比 r**。换句话说，我们要把“速度—质量前沿”往外推，而不是单纯追求最高加速比。

这里要先说清楚方向。r 越小，越省算力；但 r 越小，缓存越旧，质量越容易下降。所以“优化 r”指的是：同样的质量，用更小的 r 做到。

相对 v1 的三处主要变化：

- **问题收窄**：从“置信度缓存何时失效”收窄到“用什么信号决定何时、刷新哪里，才能在同质量下少刷新”。v1 的 mismatch 诊断保留，但只作为寻找刷新信号的手段。
- **对手明确**：竞争对象是固定刷新间隔前沿和 Elastic-Cache。已有工作发现，置信度衰减和注意力衰减两类自适应信号都打不过固定间隔，这是本计划必须跨过的门槛。
- **战场缩小**：主战场放在长生成任务。短答案任务只有约 2 步去噪，缓存几乎没有发挥空间，只作为边界证据。

## 研究问题

> **主问题：在 LLaDA-V 上，是否存在一种低成本的刷新信号，能在同等质量下比固定间隔刷新更少？**

用一个类比来理解。固定间隔刷新像“每隔 30 分钟看一次地图”。自适应刷新像“只在路口看地图”。后者更省力，前提是你能判断自己快到路口了。本研究要找的，就是这个“路口信号”。

主问题拆成三个子问题：

1. **哪里可以少刷（空间维度）**：视觉、问题、已解码回答三类位置，以及不同层，各自的“安全复用时长”是多少？
2. **何时必须刷（时间维度）**：缓存替换误差是否集中在少数去噪步？这些步能否提前预测？
3. **信号是否划算（成本维度）**：预测信号本身的开销加上它触发的刷新，是否低于同质量的固定间隔？

**不预设答案**。如果诊断发现误差在空间和时间上都很均匀，那么固定间隔就是近似最优的。这也是一个可发表的结论，它解释了为什么自适应方法屡次失败。

## 成功标准与竞争前沿

成功的定义是：在预先规定的质量档位上，新策略的端到端延迟低于固定间隔和 Elastic-Cache。所有比较都按真实墙钟时间对齐，而不是按理论 FLOPs。

### 为什么 r 是关键变量

缓存能省的，只有“非刷新步”的计算。刷新越频繁，能省的就越少。假设每步计算量近似与参与计算的 token 数成正比，可以写出粗略的加速比：

$$
\text{Speedup} \approx \frac{1}{r + (1 - r)\,\dfrac{a}{N}}
$$

- $r$：需要全量重算的步数占比，比如每 32 步刷新一次时 $r = 1/32$
- $a$：非刷新步中仍需计算的 token 数，比如当前生成块
- $N$：序列总长度，包括视觉、问题和回答 token
- $a/N$：非刷新步相对全量计算的成本比例

当 $a/N$ 很小时，加速比上限接近 $1/r$。这个公式忽略了注意力的平方项和索引开销，只用来看量级。如果新策略还引入额外的探测计算，就把它折算成一个等效的 r 增量。

### 要超越的前沿

已有实测表明，高保真区间的加速比很低。默认设置有约 11 倍加速，但输出和原模型差别很大。想接近原模型输出，就只剩约 1.3 倍。**本计划的机会就在这段中间区域**：用更少的刷新，达到间隔 4 或间隔 2 的质量。

固定间隔前沿（LLaDA-V + Fast-dLLM，50 张 MME 图像；来源：[Faster but Different](https://arxiv.org/abs/2607.29079) 表 3，加速比由墙钟时间计算）：

| 设置 | 单次生成时间（秒） | 加速比 | 与原输出的一致性（Jaccard） |
| --- | --- | --- | --- |
| 不加速 | 71.90 | 1.0× | 1.000 |
| 间隔 1 | 55.29 | 1.3× | 0.987 |
| **间隔 2（目标质量档）** | 30.11 | 2.4× | 0.666 |
| **间隔 4（目标质量档）** | 17.53 | 4.1× | 0.572 |
| 间隔 8 | 11.16 | 6.4× | 0.482 |
| 间隔 16 | 8.12 | 8.9× | 0.463 |
| 间隔 32（默认） | 6.37 | 11.3× | 0.420 |

本计划要争取的，是在间隔 2 和间隔 4 的质量上，把加速比往右推。

### 预先登记的判定规则

- **质量的两把尺子**：主指标是长生成基准的任务准确率；辅助指标是与全量重算输出的一致性（Jaccard、BERTScore）。
- **质量档位**：以固定间隔 2、4、8 三档的质量为锚点。
- **胜出门槛（2026-10-27 冻结）**：至少两个档位上，同质量的墙钟时间降低 25% 以上；并且配对检验在 Holm 校正后显著。
- **重复与不确定性（2026-10-27 决定）**：主结果用确定性解码，所有方案跑同一批样本，报告配对差值 `Δ [95% CI] (n)`（样本上的配对 bootstrap），并做配对检验（准确率用 McNemar，延迟和一致性用 Wilcoxon）。刷新时刻的微小变化会明显改变输出，所以每个胜出结论再在 50 个样本上用采样解码跑 3 个 seed，检查改进方向是否一致，作为附录。完整协议见 `.claude/research.md`。

## 诊断阶段：先画出“误差地图”

诊断的唯一目的，是回答一个问题：**缓存误差是否集中**。如果误差集中在少数位置、少数层或少数步，就有机会只刷那一小部分。如果误差很均匀，就没有省的空间。

类比一下：修缮地铁线路前，先统计哪几段轨道故障最多。故障集中，就重点巡检那几段；故障均匀，就只能按固定周期全线巡检。

### 核心测量：固定轨迹上的“替换误差”

沿全量重算的生成轨迹，在某一步把一组位置或一段层的 KV 换成若干步前的旧值，其余保持不变。然后比较两次前向对未解码位置的预测。这样测得的是“这一块缓存过时会造成多大影响”，而不受后续轨迹分叉的干扰。

替换误差用两个量表示：未解码位置预测分布的 KL 散度均值，以及 top-1 候选翻转率。翻转率更重要，因为它直接决定输出是否改变。

### 保留的 mismatch 测试

v1 的七项假设精简为五项。每一项都对应一个可能的刷新信号；存在与否决定该信号是否值得做。

| 编号 | 要回答的问题 | 方法 | 若成立，对应的省法 |
| --- | --- | --- | --- |
| D1（原 M2） | 视觉、问题、回答三组位置的安全复用时长是否不同 | 逐组替换，扫描缓存年龄 1–32 步 | 各组使用不同刷新周期 |
| D2（原 M2 细化） | 视觉内部是否只有少数 token 敏感 | 按回答对视觉的注意力分桶，逐桶替换 | 只刷新视觉中的关键子集 |
| D3（原 M6） | 误差是否集中在少数去噪步 | 在每一步单独测量“延迟刷新一步”的替换误差 | 按阶段非均匀地分配刷新 |
| D4（原 M4） | 新解码 token 的不稳定期有多长，是否随视觉依赖变化 | 按 token 类型（数字、实体、关系词、功能词）统计解码后第 1–8 步的替换误差 | 按 token 类型设定不同的缓存延迟 |
| D5（原 M5） | 局部过时是否扩散到远处或另一模态 | 只替换一组，测其他组所有位置的预测变化 | 判断“局部刷新”是否安全 |

说明：原 M1（置信度与稳定性）不再单独立项，而是作为候选信号之一在下一节检验。原 M3 和 M7 移到最终评测，用来确认省下的刷新没有伤害视觉敏感任务。

### 诊断的产出形式

产出是一张“误差集中度”表。它的含义是：如果只刷新误差最大的前 k% 的单元（位置组 × 层 × 步），能消除多少比例的总误差。例如“前 20% 单元占 80% 误差”就是强集中；“前 20% 占 25%”就接近均匀。

## 候选刷新信号与调度方案

优先尝试**零开销的静态调度**，再尝试需要在线信号的动态调度。理由是：已有工作中还没有任何在线信号打赢固定间隔，而静态调度没有信号成本。

这里有一个重要线索。已有工作发现，质量只与“有多少步是完全精确的”相关，而不与“近似得有多聪明”相关。所以本计划的策略不是发明更聪明的近似，而是**把精确刷新放在最值钱的位置和时刻**。

| 方案 | 做法 | 依赖的诊断 | 信号成本 | 与已失败信号的区别 |
| --- | --- | --- | --- | --- |
| S1 模态分离周期 | 视觉、问题、回答三组各用一个刷新周期，周期由 D1 标定 | D1 | 零 | 静态调度，不依赖在线信号 |
| S2 非均匀时间表 | 刷新步数按去噪阶段分配；例如前期密、后期疏 | D3 | 零 | 静态调度；利用 LLaDA-V 后期能弥补信息损失的先验 |
| S3 事件触发 | 当视觉依赖型 token（数字、实体、关系词）刚被解码时触发一次刷新 | D4 | 极低：只看词表类别 | 触发源是解码事件，而不是置信度或注意力的漂移 |
| S4 关键子集刷新 | 每步只重算视觉中敏感的一小部分 token，其余按长周期刷新 | D2、D5 | 低到中 | 已失败的“分块轮换”是均匀轮流；这里按敏感度选择 |
| S5 直接探测过时度 | 在一层中对少量抽样位置重算 K，差异超过阈值就全量刷新 | D3 | 中 | 测的是缓存本身的过时程度，而不是间接代理量 |

接入说明：

- **与层维度叠加**：Elastic-Cache 的“只从深层开始刷新”与上述方案正交。有效的方案应该再叠加层维度做一次测试，以证明收益不是重复的。
- **安全回退**：所有方案都保留一个长周期的全量刷新作为兜底，周期通过消融确定。
- **尝试顺序**：S1 和 S2 → S3 → S4 → S5。S5 的成本最高，只在前四种均不够时才做。

## 实验设计

主模型使用固定版本的 LLaDA-V checkpoint，不重新训练。生成长度、去噪步数和并行解码阈值全部固定，**只改变刷新策略**。

### 任务

| 任务 | 生成长度 | 作用 |
| --- | --- | --- |
| 详细图像描述（MME 图像） | 128 | 与已有前沿直接可比 |
| MathVerse、MathVista（思考模式） | 256–512 | 主准确率指标；与 Elastic-Cache 可比 |
| ChartQA、DocVQA（强制先推理再作答） | 约 128 | 检验数字和文字读取是否受损 |
| 自然配对图像基准（例如 NaturalBench，推理模式） | 约 128 | 检验缓存是否让模型“看不见”图像差异 |
| 短答案 VQA（默认 2 步） | 2 | 边界证据：预期无收益 |

强制推理会改变任务形式，所以这些结果要和官方设置分开报告。

### 基线

| 基线 | 目的 |
| --- | --- |
| 全量重算 | 质量、轨迹和延迟的参照 |
| 固定间隔刷新（间隔 1、2、4、8、16、32） | **主前沿**，所有方案都与它比 |
| dKV-Cache-Decode | Core 迁移基线 |
| dLLM-Cache | 双周期基线 |
| Elastic-Cache | 最强自适应基线 |
| 同预算随机刷新 | 检验收益是否来自“选对了时刻”，而不只是刷新得多 |
| **事后最优刷新（oracle）** | 用全量轨迹上的替换误差，把刷新放在误差最大的步；给出任何信号能达到的上限 |

oracle 是这一版计划新增的关键对照。如果连“完美预知”都只比固定间隔好一点，就说明任何在线信号都不值得做。这能在花大力气设计信号之前就得到答案。

### 指标

| 维度 | 指标 |
| --- | --- |
| 任务质量 | 各基准原生指标；数字、实体、关系错误单独计数 |
| 一致性 | 与全量输出的 Jaccard、BERTScore、完全一致比例 |
| 替换误差 | 未解码位置的 KL 散度、top-1 翻转率 |
| 系统成本 | 端到端延迟、实际 r、信号与索引开销、峰值显存 |
| 稳定性 | 配对 bootstrap 置信区间；胜出结论另做 3 个 seed 的采样解码方向检验 |

### 存储方案

固定轨迹诊断如果存原始 KV，存储量会失控。直觉上，每一步、每个位置、每一层都要存一份 K 和一份 V，总量就是这些维度相乘：

$$
M \approx S \cdot N \cdot \ell \cdot 2d \cdot b
$$

- $M$：单个样本一条完整轨迹的 KV 存储量（字节）
- $S$：去噪步数
- $N$：序列总长度
- $\ell$：Transformer 层数
- $2d$：每个位置每层 K 和 V 合起来的维度，$d$ 是隐藏维度
- $b$：每个数值的字节数，bf16 为 2

按 LLaDA-8B 公开配置粗估（$\ell = 32$，$d = 4096$，不用 GQA），$N$ 约 1000、$S = 128$ 时，单个样本约 64GB。因此采用**在线计算**：替换实验在生成过程中即时进行，只落盘 KL 和翻转率等汇总量。需要存原始 KV 时，只存少数代表层和抽样位置。

## 执行阶段与停止标准

计划分五个阶段，每个阶段末尾有一个闸门。闸门不通过时，计划不是失败，而是转向对应的负结果论文。时长为粗估，假设一人加 1–2 张 A100 级显卡。

1. **复现前沿（约 2–3 周）**：跑通全量重算、固定间隔、dKV-Cache-Decode、Elastic-Cache；在详细描述和 MathVerse 上画出各自的速度—质量曲线。
    - 闸门 1：统一生成循环与上游逐 token 一致；各间隔的加速比在已发表值 ±20%（相对）以内，Jaccard 在 ±0.05 以内，且都随间隔单调变化。不吻合就先排查实现。
2. **误差地图（约 3–4 周）**：约 100 个样本上完成 D1–D5，得到误差集中度表。
    - 闸门 2：前 20% 单元占总误差的 50% 以上（2026-10-27 冻结）。不通过 → 转向“误差均匀，固定间隔近似最优”的分析论文。
3. **oracle 上限（约 1–2 周）**：用事后最优刷新量出可争取的最大收益。
    - 闸门 3：oracle 在同质量下的墙钟时间比固定间隔低 40% 以上（2026-10-27 冻结）。不通过 → 不再做在线信号，把 oracle 结果写进分析论文。
4. **静态与低成本方案（约 3–4 周）**：依次实现 S1、S2、S3，必要时再做 S4、S5。每个方案都与固定间隔和同预算随机刷新对比。
    - 闸门 4：至少一个方案达到「成功标准」中的胜出门槛，并拿到 oracle 收益的一半以上。
5. **完整验证（约 3–4 周）**：扩大样本量；改变视觉长度、生成长度和去噪步数；与 Elastic-Cache 叠加测试；做消融和多次运行的方差统计。

整体约 12–17 周。闸门 2 和闸门 3 都在前 8 周内，所以即使方法线走不通，也能较早拿到可发表的分析结果。

## 风险与预期贡献

最大的风险是误差分布很均匀，导致没有可省的刷新。计划用闸门 2 和 oracle 在前 8 周内检验这一点。

### 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 误差均匀，oracle 收益小 | 方法线无空间 | 转向分析论文，解释自适应刷新为何屡次失败 |
| 轨迹对刷新时刻极度敏感 | 自由生成结果噪声大，小差异测不出 | 以任务准确率为主指标；多次运行；配对检验 |
| 收益与 Elastic-Cache 重叠 | 新颖度不足 | 必须做叠加实验，证明两者收益可以相加 |
| 不连续位置的索引开销 | 理论 r 下降，墙钟时间不降 | 优先按连续的位置组和层段刷新；始终报告墙钟时间 |
| 收益只在特定生成长度成立 | 泛化性受质疑 | 阶段 5 系统改变长度和步数 |

### 预期贡献

| 贡献 | 成功概率 | 说明 |
| --- | --- | --- |
| 多模态扩散模型的缓存替换误差地图 | 高 | 已有工作只测了最终输出，没有按位置、层、步分解 |
| oracle 上限：自适应刷新最多能赢多少 | 高 | 无论结果好坏都有价值，可以为后续工作划定天花板 |
| 零开销静态调度（S1、S2）打赢固定间隔 | 中 | 实现简单，易于部署 |
| 在线信号（S3–S5）打赢固定间隔 | 中低 | 一旦成功，就是第一个在该前沿上胜出的自适应方法 |

不预先承诺加速倍数。最终贡献的表述以闸门结果为准。

## 总结

本计划的目标是在 LLaDA-V 上，用更少的全量刷新达到与固定间隔相同的质量，也就是把速度—质量前沿往外推。做法是先画出缓存误差在位置、层和去噪步上的分布，再用 oracle 量出上限，最后优先尝试零开销的静态调度。即使方法未能胜出，前 8 周的误差地图和 oracle 上限也能独立成为一篇分析论文。
