## 版本说明

v3 把项目主线从“少刷新缓存”改成“学会先定稿哪个词”。缓存刷新降为主线的一个组成部分，只在最后一个阶段回来。

改动的依据来自 v2 子方向已经拿到的三条结果：

- **刷新的空间在当前设置下到头了。** MathVerse 300 题上，每题时间约为 $7.3\,\text{s} + 34.5\,\text{s} \times r$。在 k = 32 时，即使 r 降到 0，也最多再省约 12%，低于闸门 3 要求的 40%。
- **旧缓存改答案，但不改准确率。** 和不用缓存相比，对错改变的题从 6 道（k = 2）增加到 27 道（k = 32），但改对和改错几乎一样多。这说明同一道题存在多条“差不多好”的生成路径。
- **路径分岔发生得很早。** 在图像描述上，第一个不同的回答词的中位位置是第 22 个（k = 2、4）和第 8.5 个（k ≥ 8）。

三条合起来指向同一个问题：最终对错取决于少数几次关键的选词，尤其是早期。缓存只能随机地换路径；定稿策略则有机会系统地选对路径。

## 术语

- **定稿**：把某个空位上的候选词定下来，之后不再改。
- **定稿策略**：每一步决定定稿哪些位置的规则或模型。
- **先验**：只用模型自己的把握（置信度）定稿，不训练。
- **后验**：用模型之外的信号（答对的奖励、参考生成过程、标准答案）修正先验，通常要训练一个小策略。
- **NFE**：一道题用掉的前向计算次数，是解码代价的主要度量。
- **依赖图像的词**：去掉图像后，模型对它的把握明显下降的词，比如从图里读出的数字和实体。定义见阶段 C。

## 实验设置

- **模型**：LLaDA-V 官方权重，全程冻结。只训练一个小的定稿策略（参数量目标在百万级以内）。
- **解码**：分块生成，每块 32 个位置，从左到右。生成长度 256。阶段 A 确定每块的步数和阈值后固定。
- **评测集**：MathVerse testmini vision-dominant。建议用全部 **788 题**报告（待用户确认）：n = 300 时，阶段 D 要的 +3 个点约等于净多 9 道题；按 Exp 4 约 25 道不一致题的量级，McNemar 的 p 约 0.1，闸门 D 会因为功效不足而失败，而不是因为方法无效。v2 Exp 4 的 300 题是这 788 题的子集，可以继续用来对照和调试。选择题和填空题分开报告：选择题有猜中的成分，“K 次里至少一次答对”对它偏高更多。
- **训练集**：必须与评测集不重合。MathVerse 的不同版本是同一批题目换了文字和图像的分配，**不能**用其他版本训练。候选：Geo170K、MathV360K、GeoQA 训练集，或 2607.08056 用过的 VLAA-thinker 数字和选择题子集（便于和它对比），待用户选定。**无论选哪个都要去重**：MathVerse 的题目本身收集自 GeoQA、Geometry3K、UniGeo 等公开集，而 Geo170K、MathV360K 也包含这些来源。按图像感知哈希加题干文本相似度，删掉与 788 道评测题重合的训练题，并报告删除数量。
- **主指标**：相同 NFE 下的准确率，以及准确率—NFE 曲线。墙钟时间是次要指标，在阶段 E 变成主指标。
- **统计**：沿用 v2 的协议。确定性解码，每个配置跑一次，按题配对：配对 bootstrap 给出 `Δ [95% CI] (n)`，McNemar 检验，多个比较时 Holm 校正。训练出来的策略另按 `.claude/global.md` 跑至少 3 个训练种子。

### 阶段 A：分块基线（约 1 周）

在分块设置下复现先验基线：每步定最高的 k 个（LLaDA），把握超过阈值就定（Fast-dLLM），块内从左到右（阶段 0 加入）。加上一个免训练的视觉重排基线（VRCD 或 VISAGE，按代码可得性选一个）。每个基线扫几档 k 或阈值，画出准确率—NFE 曲线。

- **闸门 A（技术正确性）**：我们的生成循环在分块设置下与上游 LLaDA-V 逐 token 一致；基线曲线随 NFE 单调或近似单调。统一生成循环已经支持 `block_length`（`src/methods/refresh/loop.py`），这一步代价很小。
- 顺带测出分块后的每题时间，用来更新后面所有阶段的算力估计。
- **v2 的数字要在分块下重测。** Exp 4 是不分块的（block_length = gen_length = 256）。改成每块 32 个位置后，顺序只能在块内变化，空间比 Exp 4 小；30.3% 的基线准确率、“分岔发生得早”和 7.3 s 的固定开销都不能直接沿用。

### 阶段 B：在我们的设置上量顺序上限（约 1–2 周）

“多试几种顺序能提高准确率”在文本上已经被证明，这里不把它当新结论。阶段 B 有两个用途：量出 LLaDA-V + MathVerse 上的空间有多大，以及为阶段 D 产出模仿学习的标签。

MathVerse 只有最终答案，没有逐 token 的标准推理，所以用不了 Where-to-Unmask 那种逐 token 的 oracle。改用“多种顺序取最好”：同一道题用 K 种不同的定稿顺序各解码一次，只要有一种答对就算对。

直觉上，这衡量的是只改定稿顺序、不改模型时，最多能多答对多少题：

$$
\Delta_{\text{oracle}} = \text{Acc}_{\text{order}@K} - \text{Acc}_{\text{conf}}
$$

- $\text{Acc}_{\text{order}@K}$：K 种定稿顺序里至少一种答对的题目比例。
- $\text{Acc}_{\text{conf}}$：相同 NFE 下置信度基线的准确率。
- $\Delta_{\text{oracle}}$：后验修正理论上能争取的空间。

不同顺序由在置信度上加小扰动、随机打破并列等方式产生，每题 K = 8（待定）。

**对照**：K 次“顺序不变、只对选词采样”的解码（温度 0.5）。直觉上，多试几次本身就会提高“至少一次答对”的比例。这个对照把“换顺序”和“多试几次”分开。

**免费预演（Exp 4 数据，探索性，不作报告结果）**：把 Exp 4 的 6 个缓存配置看成 6 条被扰动的解码路径，顺序没变。“6 条里至少一条答对”比不用缓存的 30.3% 高 **+5.3 个点**（选择题 +6.4，填空题 +3.9），6 条全对只有 25.0%。也就是说，不换顺序、只靠扰动，K = 6 就已经超过 3 个点。所以 $\Delta_{\text{oracle}} \ge 3$ 这一条几乎一定通过，有判别力的是“顺序 oracle 是否高于采样对照”。

**可选性检验**：oracle 只说明 K 条路径里有答对的，不说明能挑出来。在同样的 K 条路径上，用模型自己的信号挑一条（平均置信度、路径似然），记作 self-select@K，并算它拿回了 oracle 收益的多少。
- 如果免训练的自选就拿回大部分，阶段 D 必须超过“best-of-K + 自选”这个强基线（按 K 倍 NFE 记账，思路同 Order-Token Search、SAS）。
- 如果自选拿回的很少，说明需要模型之外的后验信号，这正是主线的论据。

- **闸门 B（待冻结，建议值）**：主条件是，相同 NFE 和相同 K 下，顺序 oracle 显著高于选词采样对照（配对 bootstrap 区间不含 0）。辅助条件是 $\Delta_{\text{oracle}} \ge 3$ 个百分点。选择题和填空题分开报告；如果只有选择题通过，就按“猜中”解释，不算通过。self-select@K 的结果不进闸门，只决定阶段 D 的基线。
- 产出：每道题答对的那些顺序，作为阶段 D 的模仿学习标签。

### 阶段 C：依赖图像的词（约 1 周，与阶段 B 并行）

“多模态里置信度不能反映视觉依据”已有 VISAGE 等工作从注意力角度说明。阶段 C 的问题是：用“去掉图像”来定义的依赖关系，能否解释注意力信号解释不了的错误。

1. **标出依赖图像的词**：沿置信度基线的固定生成路径，把图像换成空白图再算一遍。空白图保持原图尺寸，这样 anyres 切出的图像 token 数不变，前缀能对齐。对每个已生成的词，比较有图和无图时它的概率。概率下降超过阈值的，算依赖图像的词。
2. **比较校准**：分别对依赖图像的词和其他词，算校准误差（ECE）。校准目标是：第 t 步对某个空位的 argmax 预测，是否等于该位置最终定稿的词（TraceLock 式）。不能用“这个词最终留下”：低置信度重掩码下，词一旦定稿就不再改，这一项恒为真，目标会退化成整题对错，变成把序列级标签硬套到每个词上。整题对错只在第 4 步按题分析。
3. **和注意力信号对比**：在同一批词上算 VISAGE 的注意力空间熵和 VRCD 的视觉显著性，看“依赖图像”标注在控制注意力信号之后，是否仍能预测出错。注意力权重需要 eager attention（sdpa / flash 不返回），这一步只在诊断时打开。
4. **定稿时机**：依赖图像的词在第几步被定稿，早定的是否更容易出错。

- **闸门 C（待冻结，建议值）**：依赖图像的词的校准误差显著高于其他词（按题配对 bootstrap，区间不含 0），并且在控制注意力信号后仍有显著的增量预测力。不通过时，多模态只作为评测场景，阶段 D 的机制分析改用注意力信号分组。

### 阶段 D：学定稿策略（约 3–4 周）

不从零设计，直接以 SAS 和 2607.08056 为起点。

**“相同 NFE”分两种情况，分开做、分开报告：**
- **D-order**：每步定稿的个数沿用置信度基线的安排，策略只决定定哪几个。NFE 天然相同，比较最干净，先做这个。
- **D-count**：策略同时决定定哪几个、定几个（类似 Fast-dLLM 的阈值），NFE 随题目变化。按平均 NFE 匹配，并画完整的准确率—NFE 曲线。

阶段 0 已确认（2026-10-31，`docs/literature_review.qmd`）：2607.08056 和 SAS 都是 D-order，所以 D-order 是和它们的公平比较。

**阶段 0 对基线实现的修正：**
- **从左到右基线**：SAS 自己的 Table 11 显示，短长度下从左到右持平或胜过 SAS。阶段 A 加入块内从左到右定稿作为先验基线，阶段 D 也要比它。
- **SAS 式基线要在我们的设置下重训。** SAS 每步只定一个词；按它的 Table 7，并行定 k 个时直接套用会退化。它的奖励是标准推理文本的 teacher-forced 似然，而 MathVerse 只有答案，所以要么选带推理过程的训练集、保留原奖励，要么换成答对奖励并记为偏离。另外，这个奖励每揭开一个词就要一次前向，在约 2.3k 个提示词（以图像为主）的 LLaDA-V 上代价高。SAS 有开源代码（`jimmyxu123/SAS_code`，策略约 0.33M 参数），可以直接改。
- **2607.08056 式基线只能重建。** 没有公开代码；顺序模块（UPM）的结构要从 DCoLT（2505.10446）找。论文没写清是否冻结基座，我们冻结基座，记为偏离。它的增益是单次运行、没有误差棒，部分可能来自修复 MMaDA 的“只答一个词”坍缩，LLaDA-V 不一定有这个问题。

- **D1 模仿学习**：用阶段 B 答对的顺序当标签，再加 TraceLock 式的“这个词能否留到最后”标签。输入是冻结模型的置信度和隐状态。代价低，先确认可学。
- **D2 强化学习**：以答对为奖励，组内比较（GRPO）。从 D1 的策略初始化。可能的话复用 Learning Unmasking Policies（2512.09106）的开源代码。
- **D3 机制分析**：比较学出来的策略和置信度基线，看哪些词被提前或推迟定稿，收益是否集中在依赖图像的词上（用阶段 C 的标注）。
- **基线**：置信度规则；同 NFE 的随机顺序；阶段 A 的视觉重排方法；SAS 式策略（奖励来自模型自身的路径似然）；2607.08056 式策略（隐状态输入的 GRPO 顺序模块），在 LLaDA-V 上重新实现；阶段 B 的 best-of-K + 自选（按 K 倍 NFE 记账，放在准确率—NFE 曲线上比较）。
- **闸门 D（已冻结为改写版，见 `.claude/research.md`：预先指定一个策略，相同 NFE 下比置信度基线高 ≥ 5 个点且配对 bootstrap 区间不含 0；以下为原建议值）**：至少一个策略在相同 NFE 下比置信度基线高 ≥ 3 个百分点，Holm 校正后显著，拿到阶段 B 上限收益的 50% 以上，且不低于 SAS 式和 2607.08056 式基线。前提是评测集用 788 题；如果维持 300 题，阈值需要按功效重新定，冻结前先算一次功效。

### 阶段 E：定稿与缓存联合（约 2 周）

“已定稿的词缓存稳定”由 dKV-Cache 证明过，不再验证。把 v2 子方向的刷新代码接回来，让策略额外决定何时刷新。按 v2 的 Exp 5，问题文字和深层对旧缓存最敏感，可以作为优先刷新的候选（该结论来自图像描述，MathVerse 尚未验证）。

- **基线**：分块 + 固定间隔刷新；EntropyCache；Polestar（两者都需要移植到 LLaDA-V）。
- **闸门 E（待冻结，建议值）**：同等准确率下，墙钟时间比最强的免训练联合方法低 ≥ 15%。

整体约 10–13 周。阶段 B 和 C 在前 5 周内，可以较早判断主线是否成立。

## 风险

- **竞争者推进。** 2607.08056 已经在多模态上学了顺序策略，可能很快扩展到更多模型。应对：把重心放在它没做的机制分析（依赖图像的词）和效率维度上，尽早拿到阶段 C 的结果。
- **顺序上限太小。** 如果闸门 B 不通过，说明在这个模型和任务上，顺序不是瓶颈。届时按 bad-case 分析找杠杆，比如换更长的生成或更难的题。
- **上限有水分。** “K 种取最好”天然偏高。选词采样对照就是为了把这部分剥离。
- **后验只在少步数时有效。** 2610.31576 的摘要显示，学习式策略在中等目标下只是“有竞争力”。所以主指标定为相同 NFE 下的准确率，并画完整曲线。
- **训练数据分布偏移。** 训练集和 MathVerse 的题型不同，策略可能学到数据集特定的模式。阶段 D 的报告要同时给出训练集内部的验证结果。
- **训练集与评测集重题。** MathVerse 的题目来自 GeoQA、Geometry3K 等公开集，候选训练集也包含它们。按“实验设置”中的规则去重。
- **统计功效不足。** n = 300 时，+3 个点很难在 Holm 校正后显著。应对：评测集扩到 788 题，或者冻结闸门前先按功效调整阈值。
- **文献细节未全部核实。** 除 2607.08056 外，其他工作的细节来自摘要和论文页面，阶段 0 会补读关键全文。

## 备用主线：Lafa 上的定稿（2026-10-31 加入）

主线（LLaDA-V）走不通时启用。启用与否由用户决定，计划只写触发条件和第一步。

### 为什么 Lafa 的定稿不一样

Lafa（arXiv 2610.28559，`lafa-hf/lafa-{0.5B,7B,8B}`）是分块因果的连续流语言模型：在词嵌入空间里做 flow matching，每块 4 个位置，已提交的块进 KV 缓存。下面的事实读自 `large-flow-lms` 的 `generate` / `_euler_denoise_block`（commit `607984b`），以及 dKV-ARKV 和 Self-Augmented-Retrieval-Plus-Lafa 两个项目的记录：

| | 掩码扩散（LLaDA / LLaDA-V） | Lafa |
|---|---|---|
| 未定位置的状态 | 离散：要么是 `[MASK]`，要么已定稿 | 连续：4 行都是带噪的嵌入，每步用软预测 `probs @ E` 往前推，没有“已定 / 未定”之分 |
| 什么时候定稿 | 每步都可以定一部分位置 | 只在一块的 K 步 Euler 全部跑完后，统一取一次 argmax |
| 定哪些 | 块内任意位置，不必从左到右 | 只能是**左前缀**：第 1 个词必定提交，之后按置信度阈值保留最长前缀（`threshold`，默认 0 即 4 个全提交）；其余丢掉，下一块从噪声重来 |
| 可选的决策 | 顺序（定哪几个）和个数 | 前缀长度（1–4）、每块的 Euler 步数、CFG 强度。没有“顺序”可选 |
| 已知事实 | 置信度顺序不是最优（见“已有工作”） | Lafa-8B 在 GSM8K 上，flow 模式要 CFG 8 + 自条件且 K ≥ 4 才追上 AR（0.96 对 0.97）；约 78% 的块在第一行就已是最终的词；自推测模式（输出 = AR 贪心）比串行 flow 快约 8.5 倍（dKV-ARKV L-1） |

所以 v3 主线的“定稿顺序”在 Lafa 上不存在，对应的问题变成**每块提交多长、跑几步**，性质上接近阶段 D 的 D-count：同时影响准确率和 NFE。先验是前缀置信度阈值，后验修正就是学一个前缀长度 / 停步策略。

### 和主线的取舍

- **失去的**：Lafa 只有文本，阶段 C（依赖图像的词）和“多模态 + MathVerse”这个空白都不再适用；评测改为文本数学（GSM8K、MATH-500）。
- **得到的**：连续流 LM 上的定稿 / 提交策略，目前没有找到前人工作（Self-Augmented-Retrieval-Plus-Lafa 的调研：连续 / 潜空间 DLM 上没有检索类方法；定稿策略待阶段 L0 核查）。
- **最大的风险**：在 batch 1 下，flow 模式整体输给 Lafa 自己的自推测模式。任何 flow 内的定稿策略都要把自推测作为参照，否则效率结论不成立。

### 触发条件（待用户确认）

满足任一条时，由用户决定是否切换：
1. 闸门 B 主条件不通过：在 LLaDA-V 分块设置下，顺序 oracle 不高于采样对照，说明顺序不是瓶颈；
2. 阶段 0 发现 2607.08056 或其他工作已经覆盖 LLaDA-V + MathVerse + 机制分析。

闸门 C 不通过不触发切换，那时只是多模态退为评测场景。

### 阶段

- **L0（约 3 天，只用 CPU）**：复用 dKV-ARKV L-1 的逐步 trace（`~/dKV-ARKV/results/l1_lafa/18003407/`，Lafa-8B，GSM8K 开发集 100 题，K 至 8），统计每行 argmax 在第几步定下、阈值前缀的长度分布、提前定稿的行最终对不对，算出“提前停步”和“变长前缀”在 NFE 上最多能省多少。同时做文献核查：连续流 / 潜空间 LM 上有没有提交策略方面的工作。
- **L1（约 1 周）**：在 Lafa-7B / 8B 上画先验基线的准确率—NFE 曲线（K 网格 × 前缀阈值网格），并用 oracle 前缀长度 / 停步给出上限；参照点是 AR 和自推测。复用 `sarlafa` 环境和已下载的权重。
- **L2**：L1 的上限够大才做，学一个前缀长度 / 停步策略，方法沿用阶段 D（先模仿 oracle，再 RL）。

- **闸门 L1（待冻结，建议值）**：oracle 前缀 / 停步在 Lafa 默认 flow 设置（K 4，CFG 8，自条件）的准确率 ±1 个点内，NFE 降低 ≥ 30%；并且先验阈值基线达不到这一点（否则没有后验修正的空间）。

### 算力粗估

L0 不用 GPU。L1：Lafa flow 模式每题约 20–30 秒（约 120 ms/词 × 约 200 词，来自 dKV-ARKV L-1），GSM8K 开发集 100 题 × 约 12 个配置 ≈ 8 GPU 小时；测试集上 3–4 个配置 × 1319 题 ≈ 30–45 GPU 小时。L2 视 L1 结果另估。
